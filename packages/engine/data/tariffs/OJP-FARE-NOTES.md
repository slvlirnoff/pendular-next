## Documented format (cookbook "Preisauskunft mit OJP Fare", German page; English URL given was a 404)

- `POST https://api.opentransportdata.swiss/ojpfare`, API key in `Authorization: Bearer <key>`.
- OJP Fare works with **OJP 1.0 and 2.0** XML. The client uses 1.0 (the cookbook shows only 1.0 in full;
  2.0 differs by namespaces, `Leg` instead of `TripLeg`, and `EntitlementProducts/EntitlementProduct`).
- Body: `OJP/OJPRequest/ServiceRequest/ojp:OJPFareRequest` containing one or more
  `ojp:TripFareRequest/ojp:Trip` and `ojp:Params`. The Trip is the `ojp:Trip` of an OJP trip result:
  TripId, Duration, StartTime, EndTime, Transfers, and `TripLeg`s with `TimedLeg` (LegBoard,
  LegIntermediates, LegAlight with `StopPointRef`, name, timetabled times, Order; and `Service` with
  OperatingDayRef, JourneyRef, LineRef, DirectionRef, Mode/PtMode, PublishedLineName, OperatorRef,
  DestinationText) and `TransferLeg`s. Stop refs are Swiss stop numbers such as `8501120`.
- Params: `FareAuthorityFilter` (ch:1:NOVA, ignored), `PassengerCategory` (ignored), `TravelClass`
  (`first`/`second`), `Traveller` with `Age` (**ignored**), `PassengerCategory` (**ignored**) and
  `EntitlementProduct` = `HTA` (Half Fare, the **only** supported entitlement: set -> half-fare prices,
  absent -> full price). No GA, no other passes, no Mobilis products: confirms "ignores age, no passes".
- Response: `ojp:OJPFareDelivery` with `Status`, `ojp:FareResult/ojp:TripFareResult` (each with
  FromTripLegIdRef/ToTripLegIdRef and an `ojp:FareProduct`: FareProductId, FareAuthorityRef/Text,
  `Price` (gross, CHF), `NetPrice`, `Currency`, `VatRate`, `TravelClass`). The example shows one
  result per class. Several results for different leg ranges mean several tickets for one trip.
  The response does not say whether HTA was applied, hence the `half` hint in `parseFareResponse`.
- Documented behaviour and limits: only future trips; only public transport legs priced (walk/on-demand
  not); only prices inside Switzerland (no foreign stops, Leman Express not priced unless tariff
  association/tariff code); saver tickets (Sparbillette) are included when they exist (normal ticket =
  product 125, e.g. BLS Bern - Zweisimmen product 84004), so a result may be cheaper than the standard
  fare; day passes can be substituted when no first-class ticket exists (product **2361**, must be
  filtered: `totalForClass` drops it); city/association fares can mask the route price (Mattelift/Libero
  case); quotes are indicative only. Rate limit 50/min, 20 000/day (gateway headers confirm 50/min).
- Date range accepted: **unknown** (could not be tested). The cookbook only says "must be in the future".
  The current timetable ends 2026-12-12; whether 2027-01-19 is accepted is open.

## Client behaviour (src/fares/ojpFare.ts)

- `buildFareRequest`: drops non-transit legs, inserts a `TransferLeg` between consecutive transit
  legs, converts times to UTC `Z`, sends the leg's `stopId` as StopPointRef (missing stopId throws),
  interpolates intermediate stop times evenly (the engine has none), synthesises JourneyRef/LineRef
  (`ojp:pendular:...`, `ojp:<operator>:<line>`) because the engine has no real journey ids. **These
  synthetic refs are unverified**: the service may need real JourneyRefs to find the trip.
- `parseFareResponse`: returns [] on `ErrorCondition`, `Status=false` or no priced product.
- `quote`: per class the cheapest alternative per leg range, summed over ranges; day pass 2361 dropped.
  Cache key = stop sequence + class + half (failures are not cached); requests are serialised with
  >= 1300 ms spacing; 6 s timeout; token from `token` option or `OJP_FARE_TOKEN`, else null.
- Stop ids: the engine's `stopId` is passed as is. SLOIDs (`ch:1:sloid:4121`) were not tried.
